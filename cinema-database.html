Relational Database Management & Analytics Case Study

Cinema Database Design & Business Analysis

Translating complex movie theater operations into a normalized relational database schema and authoring multi-table SQL queries to answer operational, revenue, and customer analytics questions.

Project Type Team Project (Cinema Schema)
Academic Context Information Systems & Analytics • LSU
Core Technologies SQL, MySQL, Relational Modeling

Project Overview

As part of a team database design project, we designed a relational database for a movie theater business that needed to organize movies, showtimes, auditoriums, customers, employees, ticket sales, and concession activity. The project focused on translating business processes into a structured relational database and using SQL to answer operational and analytical business questions.

Team Collaboration Note: This project was developed as a collaborative initiative by the Cinema Schema team (Kylie LaCaze, Elle Dieterich, Casey Tran, Tyler Le). Individual contribution details will be provided separately.

Business Problem

Our client is a commercial movie theater business that sells tickets, offers concessions such as popcorn and beverages, and operates multiple auditoriums with distinct seating capacities, daily showtimes, and movie schedules. Customers purchase tickets either online or in person, and frequently buy concession items during their visit.

The primary business problem is that a movie theater generates and processes a high volume of operational data every single day. Without a properly designed, normalized relational database, managing these transactions leads to acute operational bottlenecks:

Seating & Booking Integrity

Preventing duplicate seat bookings and ensuring tickets sold never exceed an auditorium's physical seating capacity.

Auditorium Scheduling

Eliminating room scheduling conflicts by verifying movie runtimes against showtimes and auditorium assignments.

Financial Accuracy

Capturing exact ticket revenues, concession order totals, and employee order handling for financial reconciliation.

Performance Intelligence

Tracking movie genre revenue, peak attendance dates, and high-margin concession items to support operational decisions.

Database Design & Architecture

The system was designed from conceptual operational requirements through physical relational schema implementation. The database consists of 10 normalized tables structured to Third Normal Form (3NF) to guarantee referential integrity and eliminate insertion, update, and deletion anomalies.

Relational Entities & Structural Definitions

movie PK: movieid
Stores unique movie titles and durations in minutes.
Attributes: movieid, movietitle, movieduration
auditorium PK: auditoriumid
Defines physical theater rooms, room numbers (UNIQUE), and seating capacities.
Attributes: auditoriumid, roomnumber, seatingcapacity
showtime PK: showtimeid
Schedules movie showings with date, start time, and auditorium assignment.
FKs: auditoriumid → auditorium, movieid → movie
ticket PK: ticketid
Records individual ticket transactions, seat numbers, prices, and purchasing patrons.
FKs: showtimeid → showtime, custid → customer
customer PK: custid
Maintains patron directory with contact details (first/last name, email, phone).
Attributes: custid, custfirstname, custlastname, custemail, custphone
employee PK: employeeid
Tracks staff members and assigned operational roles (Cashier, Concession Clerk, Manager, Usher).
Attributes: employeeid, empfirstname, emplastname, employeerole
concession_order PK: orderid
Captures concession purchase headers linked to handling employees and customers.
FKs: employeeid → employee, custid → customer
order_details Composite PK
Line-item junction table recording items ordered and quantities.
PK/FKs: (itemid, orderid) → concession_item, concession_order

Technical Implementation

The schema was written in standard MySQL syntax, incorporating strict field data types, NOT NULL constraints, foreign key referential integrity rules, and unique room constraints.

DDL: Relational Table Creation Sample (MySQL) 
-- Example: Showtime & Ticket Entity Constraints
CREATE TABLE showtime (
    showtimeid INT NOT NULL,
    starttime TIME NOT NULL,
    showdate DATE NOT NULL,
    auditoriumid INT NOT NULL,
    movieid INT NOT NULL,
    PRIMARY KEY (showtimeid),
    FOREIGN KEY (auditoriumid) REFERENCES auditorium(auditoriumid),
    FOREIGN KEY (movieid) REFERENCES movie(movieid)
);

CREATE TABLE ticket (
    ticketid INT NOT NULL,
    seatnumber VARCHAR(10) NOT NULL,
    ticketprice DECIMAL(5,2) NOT NULL,
    showtimeid INT NOT NULL,
    custid INT NOT NULL,
    PRIMARY KEY (ticketid),
    FOREIGN KEY (showtimeid) REFERENCES showtime(showtimeid),
    FOREIGN KEY (custid) REFERENCES customer(custid)
);

Business Analysis with SQL

To validate that the database directly supports operational reporting and management decisions, our team authored and tested SQL queries targeting key business questions across revenue, concessions, scheduling, and customer activity.

Q1. Which movies generated the most ticket revenue?

Multiple Join • SUM • GROUP BY • ORDER BY

Joins movie, showtime, and ticket tables to calculate aggregate ticket gross revenue per title, sorted in descending order to identify top box-office drivers.

SQL Query
SELECT 
    m.movietitle, 
    SUM(t.ticketprice) AS total_revenue
FROM movie m
JOIN showtime s ON m.movieid = s.movieid
JOIN ticket t ON s.showtimeid = t.showtimeid
GROUP BY m.movietitle
ORDER BY total_revenue DESC;

Q3. What is the average ticket price by movie genre?

Multiple Join • AVG • GROUP BY with HAVING

Aggregates ticket sales across linked genres to assess pricing distributions, applying a HAVING clause to filter out low-volume categories.

SQL Query
SELECT 
    mg.moviegenre, 
    ROUND(AVG(t.ticketprice), 2) AS avg_ticket_price
FROM movie_moviegenre mg
JOIN showtime s ON mg.movieid = s.movieid
JOIN ticket t ON s.showtimeid = t.showtimeid
GROUP BY mg.moviegenre
HAVING COUNT(t.ticketid) >= 1
ORDER BY avg_ticket_price DESC;

Q6. Which concession items generated the highest revenue?

Multiple Join • Arithmetic Aggregation • ORDER BY

Multiplies item unit price by line-item order quantities across orders to compute total concession income per item.

SQL Query
SELECT 
    ci.itemname, 
    SUM(ci.itemprice * od.orderquantity) AS concession_revenue
FROM concession_item ci
JOIN order_details od ON ci.itemid = od.itemid
GROUP BY ci.itemname
ORDER BY concession_revenue DESC;

Q9. Which movies belong to the Action genre?

Subquery • IN Clause • Relational Filtering

Demonstrates nested subquery logic to select movies dynamically based on genre classifications in the bridge table.

SQL Query
SELECT movietitle, movieduration
FROM movie
WHERE movieid IN (
    SELECT movieid 
    FROM movie_moviegenre 
    WHERE moviegenre = 'Action'
);
