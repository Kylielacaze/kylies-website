Relational Database Management & Analytics Case Study

Cinema Database Design & Business Analysis

Translating commercial movie theater operations into a normalized relational database schema in MySQL and authoring multi-table SQL queries to answer operational, revenue, and customer analytics questions.

Project Type Applied Team Project (Cinema Schema)
Academic Context Information Systems & Analytics • LSU
Core Technologies SQL, MySQL, Relational Modeling
Database Architecture 3rd Normal Form (3NF), 10 Relational Tables

Project Overview

As part of an applied team database design initiative, we designed and implemented a relational database for a commercial movie theater business managing movies, showtimes, auditoriums, customers, employees, ticketing, and concession operations. The project focused on transforming operational workflows into a structured relational schema and writing multi-table SQL queries to answer critical executive business questions.

Team Collaboration Note: Developed collaboratively by the Cinema Schema team (Kylie LaCaze, Elle Dieterich, Casey Tran, Tyler Le).

Business Problem & Operational Challenges

A multi-auditorium cinema operates a fast-paced environment involving continuous point-of-sale transactions across ticketing counters, concession stands, and online reservations. Without a normalized relational architecture, daily operations face critical integrity risks:

Seating & Capacity Integrity

Preventing double-booked seats and enforcing physical room capacity limits on showtime ticket sales.

Auditorium Scheduling

Preventing overlapping showtime conflicts by validating movie runtimes against room availability.

Financial Accountability

Accurately capturing ticket sales, concession line-items, and employee handling for audit reconciliation.

Executive Reporting

Providing reliable data structures to evaluate genre box-office trends, concession margins, and peak traffic.

Database Design & Relational Schema Architecture

The system was designed from conceptual operational requirements through physical relational schema implementation. The database consists of 10 normalized tables structured to Third Normal Form (3NF) to guarantee referential integrity and eliminate insertion, update, and deletion anomalies.

movie PK: movieid
Stores unique movie titles and durations in minutes.
Attributes: movieid, movietitle, movieduration
auditorium PK: auditoriumid
Defines physical theater rooms, room numbers (UNIQUE), and seating capacities.
Attributes: auditoriumid, roomnumber, seatingcapacity
showtime PK: showtimeid
Schedules movie showings with date, start time, and auditorium assignment.
FKs: auditoriumid → auditorium, movieid → movie
ticket PK: ticketid
Records individual ticket transactions, seat numbers, prices, and purchasing patrons.
FKs: showtimeid → showtime, custid → customer
customer PK: custid
Maintains patron directory with contact details (names, email, phone).
Attributes: custid, custfirstname, custlastname, custemail, custphone
employee PK: employeeid
Tracks staff members and assigned operational roles (Cashier, Concession, Manager, Usher).
Attributes: employeeid, empfirstname, emplastname, employeerole
concession_order PK: orderid
Captures concession purchase headers linked to handling employees and customers.
FKs: employeeid → employee, custid → customer
order_details Composite PK
Line-item junction table recording items ordered and quantities.
PK/FKs: (itemid, orderid) → concession_item, concession_order
concession_item PK: itemid
Catalog of available concession items, pricing, and product descriptions.
Attributes: itemid, itemname, itemprice
movie_moviegenre Composite PK
Junction table supporting many-to-many relationships between movies and genres.
PK/FKs: (movieid, moviegenre) → movie

Technical Implementation & DDL Constraints

The schema was authored in standard MySQL syntax incorporating strict data types, NOT NULL constraints, foreign key referential integrity cascades, and unique constraints.

MySQL DDL Table Creation Sample 
-- Example: Showtime & Ticket Entity Constraints
CREATE TABLE showtime (
    showtimeid INT NOT NULL,
    starttime TIME NOT NULL,
    showdate DATE NOT NULL,
    auditoriumid INT NOT NULL,
    movieid INT NOT NULL,
    PRIMARY KEY (showtimeid),
    FOREIGN KEY (auditoriumid) REFERENCES auditorium(auditoriumid),
    FOREIGN KEY (movieid) REFERENCES movie(movieid)
);

CREATE TABLE ticket (
    ticketid INT NOT NULL,
    seatnumber VARCHAR(10) NOT NULL,
    ticketprice DECIMAL(5,2) NOT NULL,
    showtimeid INT NOT NULL,
    custid INT NOT NULL,
    PRIMARY KEY (ticketid),
    FOREIGN KEY (showtimeid) REFERENCES showtime(showtimeid),
    FOREIGN KEY (custid) REFERENCES customer(custid)
);

Business Analysis with SQL

To validate that the relational model actively supports operational decision-making, we authored and executed SQL queries answering strategic business questions across revenue, pricing, concessions, and scheduling.

Q1. Which movies generated the highest gross ticket revenue?

Multi-Table Join • SUM • GROUP BY • ORDER BY

Joins movie, showtime, and ticket tables to compute total ticket gross per title, ranked in descending order.

SQL Query
SELECT 
    m.movietitle, 
    SUM(t.ticketprice) AS total_revenue
FROM movie m
JOIN showtime s ON m.movieid = s.movieid
JOIN ticket t ON s.showtimeid = t.showtimeid
GROUP BY m.movietitle
ORDER BY total_revenue DESC;

Q3. What is the average ticket price by movie genre?

Multi-Table Join • ROUND • AVG • HAVING

Aggregates ticket sales across linked genres to assess pricing distributions, using a HAVING clause to filter categories.

SQL Query
SELECT 
    mg.moviegenre, 
    ROUND(AVG(t.ticketprice), 2) AS avg_ticket_price
FROM movie_moviegenre mg
JOIN showtime s ON mg.movieid = s.movieid
JOIN ticket t ON s.showtimeid = t.showtimeid
GROUP BY mg.moviegenre
HAVING COUNT(t.ticketid) >= 1
ORDER BY avg_ticket_price DESC;

Q6. Which concession items generated the highest revenue?

Join • Arithmetic Aggregation • GROUP BY

Multiplies item unit prices by line-item order quantities across orders to compute total concession income per item.

SQL Query
SELECT 
    ci.itemname, 
    SUM(ci.itemprice * od.orderquantity) AS concession_revenue
FROM concession_item ci
JOIN order_details od ON ci.itemid = od.itemid
GROUP BY ci.itemname
ORDER BY concession_revenue DESC;

Q9. Which movies belong to the Action genre?

Nested Subquery • IN Clause

Demonstrates nested subquery logic to select movies dynamically based on genre classifications in the bridge table.

SQL Query
SELECT movietitle, movieduration
FROM movie
WHERE movieid IN (
    SELECT movieid 
    FROM movie_moviegenre 
    WHERE moviegenre = 'Action'
);

Key Competencies & Technical Takeaways

  • Translating Real-World Operations into Relational Schemas: Gained hands-on experience distilling high-volume theater workflows (ticketing, room assignments, concessions) into structured relational tables that systematically prevent data redundancy.
  • Enforcing Integrity at the Database Layer: Structured foreign keys, composite primary keys, and unique attributes to guarantee transactional consistency and referential integrity directly at the schema level.
  • Bridging Raw Data to Executive Analytics: Authored performant SQL queries to uncover revenue drivers, concession margins, and customer patterns to support data-backed management decisions.
